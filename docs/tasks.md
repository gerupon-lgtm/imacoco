## 5. タスク詳細

### T-001: 雛形・CI・バージョン

- 依存: なし
- 完了条件: Node 24 LTS、React、TypeScript、Vite、Vitest、Playwright、vite-plugin-pwaの雛形を作り、dev/build/typecheck/testが成功する。package.jsonを版の正典にし、mvp-0.1.0をフッター用定数とキャッシュ名へ生成する。
- 検証方法:
  - 正常: npm run checkとnpm run buildが成功し、distが静的配信できる。
  - 異常: 版定数を意図的にずらすとcheck-versionが失敗する。
  - 境界: MINOR／MAJOR更新で下位版が0へ戻らない入力を拒否する。
  - CI: TZ=UTC、Node 24、package-lock.jsonによるnpm ciで実行する。

### T-002: 日時・距離・方角の共通処理

- 依存: T-001
- 完了条件: Unix秒／UTC ISO／JST表示、JSTローカル日、ヘッダー用の日付・曜日・HH:mm、次の分境界／JST日付境界までの更新計算、Haversine距離、初期方位角、8方位、距離表示を純粋関数で提供する。
- 検証方法:
  - 正常: 東京駅と既知地点の距離・方位が許容差内。
  - 境界: 同一点、経度180度跨ぎ、無効座標、1km表示境界。
  - 日時: 毎分のHH:mm更新、JST 23:59→00:00の日付・曜日切替、月末月初、UTCとJSTで日付が違う瞬間をTZ=UTCで検証。
  - 復帰: バックグラウンド経過後は加算値でなく現在時刻から再計算し、分・日付のずれが残らない。
  - 禁止検査: +09:00手動加算やタイムゾーンなし文字列の暗黙new Date解析を使わない。

### T-003: IndexedDB・設定・期限

- 依存: T-001、T-002
- 完了条件: 最新位置・表示・資源キャッシュを保存し、距離別15分判定、24時間期限、最新1件上書き、形式移行、全消去を実装する。
- 検証方法:
  - 正常: 249m／999mかつ14分59秒で対象キャッシュを再利用。
  - 境界: 250m／1km／15分／24時間の直前直後を時計固定で検証。
  - 異常: 破損JSON、未知schemaVersion、保存容量エラーで画面を停止しない。
  - 競合: 全消去を2並行実行しても残存データ0、成功結果は1つ。

- 作業記録（2026-08-11、T-004／T-007／T-009／T-010／T-020）: モバイルの主タイトル一行化と再拡大、テーマ選択を更新・共有と同じ操作群へ集約して枠線色も統一、住所取得時刻と重複するヘッダー更新時刻の削除、ダーク時のヘッダーアイコン、天気の気温・状態配置、カード見出しと住所・駅の地図操作の統一、駅・役所・医療機関に共通する直線距離注記の一箇所化、保存済み情報のフッター集約、ライト背景の明度を調整し、Playwrightの視覚寸法・コントラスト検証へ反映した。

### T-007: 天気・太陽・概算標高

- 依存: T-002、T-004
- 完了条件: Open-Meteo応答を正規化し、現在、今日最高／最低、降水確率、次6時間、日の出／日の入りを別カードへ段階表示する。同じ応答の標高を整数mへ丸め、現在地カードに「標高 約○m（概算）」と表示する。
- 検証方法:
  - 正常: Unix秒をUTC保存・JST表示し、現在以降6件だけ選ぶ。
  - 異常: currentだけ、dailyだけ、配列長不一致、null、未知WMOコード、timeout。
  - 標高: `elevation=10.0`は「標高 約10m（概算）」、欠損・NaN時は標高行だけ非表示で天気・現在地を維持し、標高専用通信が0件である。
  - 日付境界: JST 0時直後に今日のdaily行を選び、UTC日付で前日を選ばない。
  - キャッシュ: 999m／15分未満は再利用、1km以上または手動更新は再取得。

### T-008: 概算潮汐

- 依存: T-002、T-004
- 完了条件: Marine APIのsea_level_height_mslから極大・極小を抽出し、30km以内だけ「潮の目安」と基準距離・免責を表示する。
- 検証方法:
  - 正常: 人工的な半日周期系列からhigh/lowが交互に最大4件出る。
  - 境界: 29,999mは対象、30,001mは対象外、候補1件は不足扱い。
  - 異常: null系列、一定値、欠損時刻、timeout、遅延応答。
  - 外部整合: 気象庁代表地点の同日満干潮と順序・大幅乖離を参考比較し、同値は要求しない。
  - 表示: 「正確」「航海可能」と読める文言や潮位の強調表示がない。

  - データ: 設置終了年9999かつ原典で休止と確認できない駅だけを採用し、原典件数＝採用＋除外、除外理由、関係ID重複0、座標範囲、データ基準日、非商用条件、出典を検査する。
  - 外部整合: 都市部・地方・指定都市・路面電車の代表駅について、駅名、路線、運営会社、現存状況を鉄道事業者公式サイトと突合する。

  - キャッシュ: 249mかつ15分未満は再利用、250m以上または手動更新は再検索する。

## 7. 変更停止条件

実装・試験で次が判明した場合、設計だけで回避せず要件改訂を先に行う。

- 無料API条件が非商用・0円要件を満たさない。
- 国土地理院系サービスがブラウザから利用不能になり、代替提供元追加が必要。
- 医療5区分の公式データが取得・再配布できない。
- 国土数値情報の鉄道時系列データが非商用利用、加工・再配布、または駅属性の要件を満たさない。
- 概算潮汐が利用者に正確な潮汐と誤解され、表示方式または機能停止が必要。
- 埋め込み地図、手入力、ログイン、サーバー保存などMVP外機能が必要になった。
